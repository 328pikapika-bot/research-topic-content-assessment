# Docker 镜像打包 Skill

## 目标

为单个项目生成可直接用于交付的 Docker 打包文件，覆盖前端 Vue 项目、后端 Java/Python 服务项目，以及 `docker-compose.yml` 编排文件。

## 适用场景

- 为每个项目单独生成镜像文件
- 为多个前端/后端项目批量生成打包方案
- 为 Vue 项目生成基于 `nginx` 的静态站点与反向代理配置
- 为后端服务生成支持环境变量切换运行环境的 Docker 打包方案
- 为所有镜像统一处理北京时间时区

## 生成规则

### 1. 项目拆分

- 每个项目独立生成一个镜像。
- 前端 Vue 项目、后端 API 项目、独立服务项目分别生成各自的 Dockerfile 与配套配置。
- 镜像命名遵循：`docker-hosted.example.invalid/nstl/项目名-前后端名称:版本号`

### 2. Vue 项目

- 使用 `nginx` 作为 Web 容器。
- 将 Vue 构建产物复制到 `nginx` 的站点目录。
- 为前端请求配置 `nginx` 反向代理，把后端接口请求转发到真实服务地址。
- 默认输出以下文件：
  - `Dockerfile`
  - `nginx.conf` 或 `default.conf`
  - `docker-compose.yml`

### 3. 后端项目

- Docker 镜像需要通过环境变量控制运行环境，例如 `ENV=test` 或 `ENV=prod`。
- 生成的启动命令应支持读取环境变量并映射到应用配置。
- 对于 Java/Python 项目，优先生成通用且可改造的模板，不绑定单一框架实现。

### 4. 时区处理

- 所有镜像统一设置为北京时间。
- 默认写入 `TZ=Asia/Shanghai`。
- 如有需要，补充系统时区数据包安装或软链接配置。

### 5. 远程打包与发布提示

- 在生成的 `Dockerfile` 注释或末尾附带远程构建与推送提示：
  - `docker -H tcp://127.0.0.1:2375 build -t 镜像名:版本号 .`
  - `docker -H tcp://127.0.0.1:2375 push 镜像名:版本号`
- 仅作为注释或说明，不要替代正常 Dockerfile 指令。

### 6. docker-compose

- 为每个项目生成可运行的 `docker-compose.yml`。
- Compose 文件应支持端口映射、环境变量、挂载与服务依赖。
- 如果项目包含多个镜像，compose 应明确拆分服务名称与镜像名。

## 工作流程

1. 识别项目类型：Vue 前端、后端服务，或两者混合。
2. 收集构建产物路径、端口、后端地址、运行环境变量名。
3. 生成对应的 `Dockerfile`、`nginx` 配置、`docker-compose.yml`。
4. 检查镜像名、时区、环境变量与反向代理规则是否符合约束。
5. 若用户未提供关键信息，使用可编辑占位符并明确标注需要替换的字段。

## 输出要求

- 生成的文件应可直接落地到项目目录。
- 配置内容应尽量通用、简洁、可维护。
- 默认采用最少假设原则，并保留可替换参数。
